# Lean Docs

## 规矩

一条事实只写一处，改就改原处。用不上的内容一处也不留，每段读一遍就懂。

## 怎么做

按结果验收，不按写法验收：

1. 读者打开第一句就知道这份文档是给谁、解决什么，不用往下探才知道要不要读。
2. 读者照着它做事时，用不上的内容一处也没有——哪怕那内容本身有点用。
3. 一条信息只有一个出处：读者不会在两处读到两个版本，改的人也只需改一处。
4. 读者读到的永远是当前有效的版本：被推翻的说法不在文档里留着，会过期的结论带日期或版本。
5. 每一段读一遍就能拿全意思，而且没有更短的说法能达到同样效果。
6. 用户点名要的详尽文档照写。详尽是信息多，不是同一件事说很多遍。

## 什么算没做到

- 同一个结论在「概览」「方案」「FAQ」三处各写一遍，改一处，另两处还是旧的
- 「旧方案」和「新方案」并排摆着，没写哪个生效
- 改了行为却新开一节「## 更新记录」，原段落一字未动
- 有一节叫「扩展性考虑」或「后续可能用到的配置」，读者照着这份文档做事时一次也用不上
- 把用不上的那块缩成一句、并进上一节或挪进附录，就算处理过了
- 开头是「本文档旨在梳理……随着业务的发展……」
- 写「当前使用方案 A」，没有日期，三个月后没人知道还成不成立
- 一段里塞了三件事，得来回读两遍才拆得开
- 「X 模块是一个用来处理 Y 的模块，它的职责是对 Y 进行处理」——这句话没让读者比读之前多知道什么
- 一个结论先用「首先……其次……再次……」铺三段才给出来，铺的那三段删了不损失信息
- 为了简洁把关键前提删了，读者看完还得回来问一句
