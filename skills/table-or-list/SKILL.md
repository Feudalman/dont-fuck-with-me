# Table Or List

## 规矩

先选对载体，再往里装内容。载体不合适时换载体，不压缩内容去迁就它。

## 怎么做

1. 各项属性同类，才存在用表格的可能；不同类的项进表格，只能靠「其他」「—」或空格凑。
2. 每项都能用一句话或一个数字说完，格子才装得下；要靠压缩、概括才塞进去的，说明载体已经选错。
3. 读者要横向比同一个维度，表格省掉他记上一条的力气；要弄清每一项是什么，列表省掉他填补空格的力气。
4. 只有一项、或者一段话讲得完，两个都不用。

## 什么算没做到

- 同一列四格是「低/中/低/高」，第五格是「取决于部署规模，中小团队约两万，大团队另算」
- 表头有一列叫「备注」，六行里四行是整句
- 为了对齐三列，「支持 A、B、C 三种格式」写成「支持格式」，「需要额外适配」整句删掉
- 三个方案各有各的重点，被压进一张六列表，十一格填「—」
- 五个依赖包的版本、体积、许可证每格只剩几个字，却写成五段列表，字段名重复五遍
- 五个方案该让人逐项看清各自是什么，却给了表格——没有一格被撑破，但读完说不出方案二为什么适合
